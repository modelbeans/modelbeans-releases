# Public distribution repository

Maintain public release documentation and reviewed user-facing examples here. Keep implementation source, private repository history, internal plans/reviews, credentials and user data out of this repository.

Do not add a remote pointing to a private development repository or merge its history. Add public files deliberately. Binary installers and runtime archives belong in GitHub Release assets.

Read RELEASE_POLICY.md and LICENSING.md. Preserve the distinction between a distribution tag and implementation build provenance. Do not claim support or validation beyond the release evidence, and do not publish a release without task authorization.
