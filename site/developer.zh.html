DEVELOPER STARTER

从本地 API 开始。

先通过桌面应用验证模型，再把同一个推理服务接入自己的程序。以下示例不需要安装语言 SDK，也不需要将密钥交给外部服务。

1. 准备一个可调用的模型

  1. 在 ModelBeans 中下载或导入一个适合本机的文本模型，并完成加载。
  2. 进入 API 服务，确认服务已启动。复制界面显示的基础地址与密钥，核对可用模型名；可以使用已配置的模型别名。
  3. 将下面示例中的环境变量设置为自己的值。基础地址以 /v1 结尾；MODELBEANS_MODEL 必须是实际存在的模型名或别名。
# PowerShell：仅设置当前终端的环境变量
$env:MODELBEANS_BASE_URL = 'http://127.0.0.1:你的端口/v1'
$env:MODELBEANS_API_KEY = '你的本地服务密钥'
$env:MODELBEANS_MODEL = '你的模型名或别名'
python examples/chat.py

下载 Python API 示例 · Python 3.10+，仅使用标准库。不要把真实密钥写进源码或公开仓库。

2. 让应用托管独立服务

更深的集成采用独立子进程：你的应用启动 ModelBeans Application Service，由它使用匹配版本的 RuntimeShare 执行推理。它不是进程内 DLL 嵌入，也不要求桌面窗口一直打开。

独立开发者包尚待发布。下面的宿主示例用于准备和本地试验，需要你提供匹配的服务、运行时文件以及模型；不要假定桌面安装包就是完整的可再分发开发者包。

your-app/
  bundle/
    modelbeans-app-service.exe
    runtime/                   # 保持匹配发行版的完整运行时目录结构
      beansd.exe
      ...                      # workers、依赖库、许可证
  data/                        # 与可替换的程序文件分开存放

下载 Python 宿主示例 或 Node.js 宿主示例。Python 3.10+ / Node.js 20+，均不依赖额外软件包。

python examples/host.py "C:/my-app/bundle/modelbeans-app-service.exe" "C:/my-app/bundle/runtime" "C:/my-app/data/python"

node examples/host.mjs "C:/my-app/bundle/modelbeans-app-service.exe" "C:/my-app/bundle/runtime" "C:/my-app/data/node"

不带模型参数时只检查启动、就绪和关闭。追加一个兼容 CPU 的小型文本 GGUF 路径，可试验导入、加载与生成；示例会复制模型到独立数据目录，需要额外磁盘空间。首次导入后可用 embedded-example-model 作为最后一个参数复用已导入模型。

宿主示例负责什么？

  1. 生成随机管理员密钥，以 serve --profile embedded、独立数据目录、动态端口启动自有子进程。
  2. 读取端点回执，核对 PID 和回环地址，再检查服务就绪。
  3. 可选地导入模型、等待任务完成、加载并调用 /v1/chat/completions。
  4. 请求正常关闭；超时后仅终止自己启动的进程。

这是生命周期示例，不是完整生产宿主。不要复用桌面应用的数据目录，不要让多个服务同时写同一目录，不要只复制 beansd.exe 或打平依赖库目录。真实推理仍需在目标设备上验收。

分发与许可

随应用分发时，应一起携带匹配的服务、RuntimeShare、必要依赖、许可证和 NOTICE，并遵循各自条款。RuntimeShare 二进制使用 Apache-2.0；这不替代第三方引擎或模型权重的许可。SDK 实现源码的公开范围及独立开发者包，以后续发行说明为准。
