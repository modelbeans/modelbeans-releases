DEVELOPER STARTER

Start with the local API.

Try a model in the desktop app, then connect the same inference service to your code. These examples need no language SDK and do not send your key to an external service.

1. Prepare a callable model

  1. Download or import a text model that fits your machine, then load it in ModelBeans.
  2. Open API Services and verify that the server is running. Copy its base address and key, and check the available model name or configured alias.
  3. Set the environment variables below to your own values. The base URL ends in /v1; MODELBEANS_MODEL must be a real model name or alias.
# PowerShell: variables apply to this terminal only
$env:MODELBEANS_BASE_URL = 'http://127.0.0.1:YOUR_PORT/v1'
$env:MODELBEANS_API_KEY = 'YOUR_LOCAL_API_KEY'
$env:MODELBEANS_MODEL = 'YOUR_MODEL_OR_ALIAS'
python examples/chat.py

Download the Python API example · Python 3.10+, standard library only. Keep real keys out of source files and public repositories.

2. Host a dedicated service

For deeper integration, your app starts a separate ModelBeans Application Service process backed by a matching RuntimeShare. This is child-process embedding, not an in-process DLL. The desktop window does not need to stay open.

A standalone developer bundle is still pending. The host examples are for integration preparation and local trials. You must supply matching service/runtime files and a model. Do not assume the desktop installer is a complete redistributable developer bundle.

your-app/
  bundle/
    modelbeans-app-service.exe
    runtime/                   # Keep the matching release layout intact
      beansd.exe
      ...                      # Workers, dependencies, licenses
  data/                        # Separate from replaceable program files

Download the Python host or Node.js host. They require Python 3.10+ or Node.js 20+, with no additional packages.

python examples/host.py "C:/my-app/bundle/modelbeans-app-service.exe" "C:/my-app/bundle/runtime" "C:/my-app/data/python"

node examples/host.mjs "C:/my-app/bundle/modelbeans-app-service.exe" "C:/my-app/bundle/runtime" "C:/my-app/data/node"

Without a model argument, these check only startup, readiness, and shutdown. Append the path of a small CPU-compatible text GGUF to try import, loading, and generation. Import copies the model into a private data directory and needs extra disk space. After the first import, use embedded-example-model as the last argument to reuse it.

What does the host handle?

  1. Generate a random administrator key and start an owned child with serve --profile embedded, a separate data directory, and a dynamic port.
  2. Read the endpoint receipt, verify the child PID and loopback address, and check readiness.
  3. Optionally import a model, wait for the task, load it, and call /v1/chat/completions.
  4. Request graceful shutdown; on timeout, terminate only the process it started.

This demonstrates lifecycle management, not a complete production host. Do not reuse the desktop app’s data directory, run multiple services against the same directory, copy only beansd.exe, or flatten library directories. Real inference still needs validation on your target hardware.

Distribution and licensing

Distribute matching service/runtime files, dependencies, licenses, and NOTICE files together under their respective terms. RuntimeShare binaries use Apache-2.0; that does not replace third-party engine or model licenses. SDK source availability and standalone developer bundles will be specified in future release notes.
